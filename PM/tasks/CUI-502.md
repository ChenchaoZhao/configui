# Task: CUI-502 - PyPI Publishing & Documentation

**Milestone:** CLI & Distribution

## Description

Finalize the project's public-facing documentation and automate the release pipeline.

The README must be production-ready: include installation instructions (via `uv tool install` and `pip`), usage examples, and a clean badge row showing CI status, test coverage, supported Python versions, and PyPI version — all via dynamic SVG badges from `shields.io`.

A GitHub Actions release workflow should handle building and publishing to PyPI whenever a version tag (`v*`) is pushed. The PyPI API token is already stored in GitHub Secrets.

Separately, the existing CI workflow needs a coverage reporting step so the coverage badge stays current. The package should also be verified as installable via `uv tool install` before release.

Finally, bump the package version from `0.0.1` to `1.0.0` for the initial public release.

## Plan

### Subtask 1: Rewrite README.md

Replace the one-liner with a comprehensive README including:

- **Badge row** — CI status, test coverage, Python (3.12/3.13), license, PyPI version
- **Installation** — `uv tool install configui` and `pip install configui`
- **Quickstart** — `configui path/to/config.yaml` with CLI usage
- **CLI reference** — `-r` read-only flag, supported formats (YAML/JSON/TOML)
- **Features** — type-aware editing, comment preservation, theme support
- **Development** — local setup with hatch/uv
- **License** — MIT

### Subtask 2: Add PyPI Release GitHub Action

Create `.github/workflows/release.yml` — trigger on `v*` tags:

1. Checkout + setup Python 3.12
2. Install uv + hatch
3. Build (`hatch build`)
4. Publish to PyPI via `pypa/gh-action-pypi-publish`

### Subtask 3: Add Coverage Reporting to CI

Update existing `tests.yml` to generate and report coverage data.

### Subtask 4: Verify `uv tool install` Works

Ensure `[project.scripts]` entry point works with `uv tool install .` — verify `configui --help`.

### Subtask 5: Bump Version to 1.0.0

Update `src/configui/__about__.py` from `0.0.1` to `1.0.0`.
