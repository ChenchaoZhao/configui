## Bug Analysis

### Root Cause: Save/Save-As does not propagate UI changes to `config._data`

**`action_save`** (`app.py:202-210`):

```python
data = map_widgets_to_config(content)
self._config.update(data)      # ✅ propagates UI -> config._data
self._config.save()
```

**`_on_save_as_result`** (`app.py:217-223`):
```python
self._config.save_as(new_path) # ❌ NO config.update(data) call!
                               #    Saves stale config._data — UI changes lost
```

The Save As flow calls `save_as(new_path)` directly **without** first collecting widget values via `map_widgets_to_config()` and propagating them via `config.update()`. This means "Save As" always writes the original loaded data, discarding any user edits.

**`action_save`** works for basic cases (verified by `test_ctrl_s_saves`), but has edge-case crashes:

- Empty string in `Input(type="integer")` → `int("")` raises `ValueError`
- Empty string in `Input(type="number")` → `float("")` raises `ValueError`

Neither `action_save` nor `action_save_as` has error handling — if `config.save()` or `config.save_as()` raises (permission error, disk full, etc.), the app crashes without user feedback.

### Other Known Issues (lower priority)

- Key and value are not vertically center aligned (cosmetic CSS)
- Scrolling on the right panel doesn't work (widget.scroll_visible silently fails)
- Cannot delete data in the box (feature missing entirely)
- Save As path assumes relative path (user cannot type absolute path in filename input)
