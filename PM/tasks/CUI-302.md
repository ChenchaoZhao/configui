## Description

Implement TOML support using tomlkit for style and comment preservation.

## Implementation Plan

### 1. Create `src/configui/config/toml_config.py`

New `TomlConfig` class following `JsonConfig`/`YamlConfig`'s structure:

```python
class TomlConfig(Config):
    def __init__(self, path: str | Path) -> None:
        self._path = Path(path)
        self._data: Mapping[str, Any] = {}

    def load(self, **kwargs: Any) -> None:
        try:
            self._data = tomlkit.parse(self._path.read_text(**kwargs))
        except TOMLKitError as e:
            msg = f"Failed to parse TOML file '{self._path}': {e}"
            raise ValueError(msg) from e

    def save(self, **kwargs: Any) -> None:
        atomic_write(self._path, lambda f: tomlkit.dump(self._data, f, **kwargs))

    def save_as(self, new_path: Path, **kwargs: Any) -> None:
        atomic_write(new_path, lambda f: tomlkit.dump(self._data, f, **kwargs))
```

- `_data` directly holds a `tomlkit.TOMLDocument` (dict-like) so comments, table ordering, and inline-table style survive the load-edit-save cycle.
- Parse errors → `ValueError` (wrapped from `tomlkit.exceptions.TOMLKitError`).
- Uses `atomic_write` (already generic — no refactor needed).

## Design Notes

- **`tomlkit` is already a dependency** in `pyproject.toml` — no changes needed.
- **`SupportedConfigFormat.TOML`** already exists in `formats.py` — no changes needed.
- **`_atomic.py`** is format-agnostic — works as-is, no refactoring required.
- **Inline tables:** tomlkit preserves these natively as `tomlkit.items.InlineTable`.
- **Indentation/style:** tomlkit is a style-preserving parser — round-trip tests verify this.
- **No `tomlkit.exceptions` import needed if catching `TOMLKitError`** — import from `tomlkit.exceptions`.
