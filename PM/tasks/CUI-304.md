# Task: CUI-304 — Refactor Config Class to Support Data Update

**Status:** Draft Plan

**Milestone:** Advanced Serialization (YAML/TOML)

## Description

Add `update(self, data: dict[str, Any], ...)` to the Config protocol and all implementations.

The update must be **atomic** — validate all constraints against `_data` before mutating anything.
If validation fails, `_data` is left unchanged and an error is raised.

## Env-Configurable Behaviour

Two integer env vars (both read-once at module level, default to `0` / `1`):

| Env | Default | When `1` |
|---|---|---|
| `CONFIGUI_UPDATE_ALLOW_NEW_KEYS` | `0` | `update()` can add keys not present in `_data` |
| `CONFIGUI_UPDATE_ALLOW_MISSING_KEYS` | `1` | `update()` can skip keys present in `_data` |

Resulting behaviours:

| allow_new | allow_missing | Effect |
|---|---|---|
| 0 | 1 (default) | Block new keys; partial update OK |
| 0 | 0 | Exact match — `data.keys()` must equal `_data.keys()` |
| 1 | 1 | Fully permissive (any keys accepted) |
| 1 | 0 | Must cover all existing keys + can add new ones |

## API

```python
def update(
    self,
    data: dict[str, Any],
    *,
    allow_new_keys: bool | None = None,
    allow_missing_keys: bool | None = None,
) -> None: ...
```

- `None` → fall back to the env-var default.
- Explicit `True` / `False` → override for this call only.

## Implementation Plan

### 1. `src/configui/config/_atomic.py` — add `atomic_update()`

Add env-var defaults and the `atomic_update` function:

```python
import os

_ALLOW_NEW_KEYS: bool = os.environ.get("CONFIGUI_UPDATE_ALLOW_NEW_KEYS", "0") == "1"
_ALLOW_MISSING_KEYS: bool = os.environ.get("CONFIGUI_UPDATE_ALLOW_MISSING_KEYS", "1") == "1"


def atomic_update(
    data: MutableMapping,
    updates: dict[str, Any],
    *,
    allow_new_keys: bool,
    allow_missing_keys: bool,
) -> None:
    if not allow_new_keys:
        extra = updates.keys() - data.keys()
        if extra:
            msg = f"Keys not found in config: {sorted(extra)}"
            raise KeyError(msg)
    if not allow_missing_keys:
        missing = data.keys() - updates.keys()
        if missing:
            msg = f"Missing keys in update: {sorted(missing)}"
            raise KeyError(msg)
    for k, v in updates.items():
        data[k] = v
```

- `MutableMapping` import added for the type hint (from `collections.abc`).
- All validation happens **before** any mutation — if it raises, `data` is untouched.

### 2. `src/configui/config/_protocol.py` — add `update()` signature only

```python
class Config(Protocol):
    _data: Mapping
    _path: Path

    def load(self, **kwargs: Any) -> None: ...
    def save(self, **kwargs: Any) -> None: ...
    def save_as(self, new_path: Path, **kwargs: Any) -> None: ...
    def update(self, data: dict[str, Any], *, allow_new_keys: bool | None = None, allow_missing_keys: bool | None = None) -> None: ...
```

No env defaults here — the protocol is a pure interface contract. Defaults live in `_atomic.py`.

### 3. Subclass implementations — delegate to `atomic_update()`

Each `update()` method is a thin delegate. Example for `JsonConfig`:

```python
from configui.config._atomic import _ALLOW_NEW_KEYS, _ALLOW_MISSING_KEYS, atomic_update

class JsonConfig(Config):
    def update(self, data: dict[str, Any], *, allow_new_keys: bool | None = None, allow_missing_keys: bool | None = None) -> None:
        _allow_new = allow_new_keys if allow_new_keys is not None else _ALLOW_NEW_KEYS
        _allow_missing = allow_missing_keys if allow_missing_keys is not None else _ALLOW_MISSING_KEYS
        atomic_update(self._data, data, allow_new_keys=_allow_new, allow_missing_keys=_allow_missing)
```

Identical pattern for `TomlConfig` and `YamlConfig`. Each imports the two module-level bools + `atomic_update` from `_atomic`.
